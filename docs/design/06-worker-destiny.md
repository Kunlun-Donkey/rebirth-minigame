# 命格·人类 —《一个打工人》设计文档 v1.0

## 0. 一句话
**重生回入职第一天。地球上 64 亿人，每个人都是一条线——这一世，你撞上谁，谁的故事就和你的缠在一起。**

- 定位：全游戏的**主线命格**（默认开放），收束「天道真相」。
- 爽点三层：职场打脸（短期）→ 系统 / 异能逆袭（中期）→ 卷出地球、和天道摊牌（长期）。
- 平凡也是结局：不争不抢、安稳过完一生，寿终时判为结局「平凡一生」。

---

## 1. 架构：线路模块化（本命格先用，所有命格通用）

现有剧本是 `events/*.json` 平铺 + 全局 flag。线路一多会出三个问题：flag 撞名、看不出一条线的结构、交叉事件要知道别的线内部细节。改为 **线路（line）= 一个独立模块**：

```
data/destinies/worker/
  destiny.json         属性 / 方向 / 层 / 境界 / 死法 / 结局 / 世界线(maps) / 规则
  talents.json items.json companions.json skills.json
  systems.json         系统定义（被动修正、每季效果、任务线 id、能否封存）
  events/              通用事件池（兜底、日常、突发），和其他命格一样
  lines/               ★ 线路：一条故事一个文件
    boss_zhou.json       画饼老板老周
    scam_trip.json       海外团建
    ...
  crossings/           ★ 交叉事件：只引用各线路「导出状态」的胶水事件
    scam_x_stream.json   逃出园区 × 直播 → 反诈网红
```

### 1.1 线路文件格式
```jsonc
{
  "id": "scam_trip",                 // 线路 id，也是命名空间
  "name": "海外团建",
  "summary": "高薪外派是个坑。去了可能回不来；不去会丢工作，但别的门会打开。",
  "maps": ["city", "workshop"],      // 只在这些世界线出现（省略 = 全部）
  "stage": [0, 2],                   // 入口境界范围
  "states": {                        // ★ 对外导出的状态（别的线路 / 交叉事件只能引用这些）
    "joined": "报名了团建",
    "escaped": "逃出了园区",
    "refused": "拒绝了团建",
    "reported": "举报了公司"
  },
  "events": [                        // 普通事件格式；id 自动加前缀 scam_trip/
    { "id": "offer", "entry": true, "dir": "side", "text": "...", "choices": [
      { "text": "报名", "effect": { "state": "joined", "follow": "bus" } },
      ...
    ] }
  ]
}
```

### 1.2 线路状态（引擎新增，通用）
- 效果 `"state": "escaped"`：在线路内写，自动变成 `scam_trip=escaped`（一条线同一时刻只有一个状态，后写覆盖前写）。
- 条件 `line:scam_trip`（这条线开始了）、`line:scam_trip=escaped`（处于某状态）、`!line:scam_trip`（没碰过）。
- 跨世：`ever:scam_trip=escaped`（任何一世到达过该状态，存档里记录），用于「前世逃出来过，这一世直接报警」。
- 线路内的 id / flag / follow 自动加命名空间，**不同线路互不撞名**；引用别的线路只能用 `line:xxx=导出状态`。

### 1.3 交叉事件
- `crossings/*.json` 只做一件事：当两条（或多条）线的状态同时满足时，触发一段新剧情，可以开新线、改状态、给结局。
- 例：`line:scam_trip=escaped & line:livestream` → 「把园区的经历拍成视频」→ 结局「反诈网红」。
- 线路之间不直接互相引用，**新增一条线不用改旧线**；想让它和旧线交叉，只加一个交叉事件文件。

### 1.4 人生岔路口（hub）
- 若干「岔路口」事件（入职第一周、被裁那天、30 岁生日、存款归零、过年回家……），每个选项是不同线路的入口。
- 线路也可以自带 `entry` 事件，满足条件时进入普通抽取池。

### 1.5 系统（金手指）
- `systems.json`：`{ id, name, rarity, mods, every, line, sealable }`。
- 事件效果 `"bind": "shenhao"` 中途绑定（一世最多一个，已有时出现「双系统打架」稀有事件）；`"unbind": true` 解绑（被天道没收）。
- 每个系统自带一条任务线（`lines/sys_*.json`），系统的台词以「【叮！】」开头，UI 用专门配色。
- 默认不可封存；走通「系统认主」线后 `sealable`。

### 1.6 寿终结局（引擎新增，通用）
- `stages[].oldAgeEndings: [{ id, require }]`：寿元到头时若满足条件，判为结局而不是死法。
- 「平凡一生」：`!ever:system & line:parents=close & 心态>=8`（举例）。其他命格以后也能加。

### 1.7 工具
- `npm run lines worker`：打印线路图（入口、状态、谁引用了谁、交叉事件、通向哪些结局），检查孤立状态（导出了没人用）和死路（进入了出不去）。
- `npm run sim -- --destiny worker`：额外输出**每条线路的进入率 / 各状态到达率 / 结局分布**，保证每条线都有人走到。
- 校验：引用未导出状态 → 报错；线路没有入口 → 报错；交叉事件引用不存在的线路 → 报错。

## 6. 审核红线（本命格额外）
- 不点真实公司、品牌、地名（海外只写「海外 / 境外园区」）；讽刺对事不对人。
- 不写猝死、过劳死、轻生；犯罪题材只写起因和结果，不写暴力过程；「没能回来」点到为止。
- 反诈线带正向提示（识破、报警、救人），不教具体手法。
